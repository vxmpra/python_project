# Garden Web Service – Техническое задание

## 1. Цель проекта
Создание веб-сервиса для садоводов, предназначенного для оптимизации ухода за растениями. Сервис автоматически формирует рекомендации по поливу с учётом погодных условий, а также предоставляет советы по защите растений от болезней и вредителей.

Цель проекта — сэкономить время пользователей и повысить урожайность за счёт персонализированных рекомендаций для каждого растения с учётом города его выращивания.

## 2. Роли пользователей

### Гость
- Может просматривать каталог растений, которые можно добавить в свой сад
- Видит общую статистику проекта (количество растений, категорий в базе)

### Зарегистрированный пользователь
- Может добавлять свои растения
- Указывает город, в котором выращивается растение
- Получает персонализированные рекомендации по поливу на основе погодных данных
- Получает советы по защите от вредителей и болезней
- Может просматривать историю рекомендаций по поливу своих растений

### Администратор
- Имеет полный доступ к управлению всеми моделями через Django Admin
- Управляет категориями растений, типами растений, советами по защите и погодными данными

## 3. Модели данных (сущности)

### Plant (Растение пользователя)
- plant_type (ForeignKey → PlantType): связь с типом растения для получения характеристик
- owner (ForeignKey → User): владелец растения, обеспечивает изоляцию данных между пользователями
- city (CharField): географическая локация для персонализации рекомендаций

Каждое растение принадлежит конкретному пользователю.

### PlantCategory (Категория растения)
- name (CharField, unique): уникальное название категории (например, "Овощи", "Фрукты", "Цветы")

Связи: Связана с PlantType через ForeignKey (один-ко-многим)

Названия категорий являются уникальными.

### PlantType (Тип растения)
- name (CharField, unique): уникальное название типа растения (например, Томат, Огурец)
- category (ForeignKey → PlantCategory): классификация по категориям
- description (TextField): описание растения
- image (ImageField, optional): визуальное представление растения

Названия типов растений являются уникальными.

### WateringRecommendation (Рекомендации по поливу)
- plant (ForeignKey → Plant): связь с конкретным растением пользователя
- date (DateField): дата формирования рекомендации 
- water_amount (FloatField): расчётное количество воды в литрах
- note (TextField): детальное обоснование с учётом метеофакторов

Рекомендации формируются автоматически на основе погодных условий.

### ProtectionAdvice (Советы по защите растений)
- plant_type (ForeignKey → PlantType): привязка советов к типам растений 
- pest_or_disease (CharField): тип вредителя или болезни
- recommendation (TextField): текст совета по защите

Используется для отображения справочной информации пользователю.

### Weather (Кэш погодных данных)
Модель используется для хранения погодных данных, полученных из внешнего API, с целью:
- уменьшения количества запросов к API
- ускорения работы сервиса

**Механизм кэширования**: Погодные данные кэшируются на день (date). При повторном запросе погоды для того же города в тот же день данные берутся из БД, а не из API.

Поля:

- city (CharField): город для метеоданных
- date (DateField): дата погодных данных
- temperature (FloatField): температура воздуха в °C
- humidity (FloatField): относительная влажность в %
- precipitation (FloatField): количество осадков в мм
- description (CharField): текстовое описание погоды
- latitude (FloatField): широта (для отображения карты)
- longitude (FloatField): долгота (для отображения карты)

## 4. Ключевой функционал (User Stories)

### Добавление растения
Пользователь добавляет растение с указанием города, где оно растёт.  

**Валидация города**: Название города валидируется через OpenWeatherMap API для предотвращения ошибок ввода.

### Получение погодных данных
Система обращается к внешнему API погоды (OpenWeatherMap) для указанного города и получает актуальные погодные данные (температура, влажность, осадки).  

### Рекомендации по поливу
На основе текущих погодных данных система рассчитывает оптимальное количество воды для растения и отображает:
- рекомендации по поливу с учётом температуры, влажности и осадков,
- интерактивную карту местоположения растения (Leaflet),
- а также интерактивный график прогноза погоды на 5 дней.

**Алгоритм расчёта**:
Учитывается базовая норма полива для типа растения, которая корректируется в зависимости от температуры воздуха, влажности и количества осадков.
При экстремальных условиях (температура ниже 5 °C или сильные осадки) система автоматически рекомендует отказаться от полива.

Отображается пользователю:
- текстовая рекомендация по поливу;
- рассчитанное количество воды (л/м²);
- интерактивная карта Leaflet с указанием города растения;
- интерактивный график прогноза погоды на ближайшие 5 дней.

### Советы по защите растений
Пользователь получает текстовые рекомендации по защите растений от вредителей и болезней.  

### Работа с данными
Для получения статистики и отображения информации используются возможности Django ORM
(агрегации, фильтрация и сортировка данных).

### Визуализация данных
Система использует внешние сервисы для наглядного представления информации:
- **Текущая погода** — сводка актуальных метеоданных (температура, влажность, осадки)
- **Местоположение растения** — теперь отображается через интерактивную карту Leaflet вместо статической Яндекс.Карты, что позволяет пользователю масштабировать карту, перемещаться и видеть точное местоположение растения
- **Прогноз полива** — добавлены интерактивные графики 5-дневного прогноза полива, которые показывают температуру, осадки и краткие рекомендации по поливу при наведении на каждый день

## 5. Внешние интеграции 
- API погоды OpenWeatherMap — получение актуальных данных о температуре, влажности и осадках
- Leaflet — интерактивная визуализация местоположения растений с возможностью масштабирования, перемещения и отображения маркеров
- Chart.js — построение интерактивных графиков 5-дневного прогноза полива с подсказками о рекомендуемом поливе для каждого дня  

## 6. Безопасность
- **Авторизация**: Обязательная аутентификация для работы с растениями
- **Ограничение доступа**: Пользователь видит только свои растения и рекомендации
- **Валидация ввода**: Проверка данных через внешние API (города)
- **Защита от дублирования**: Предотвращение добавления одинаковых растений в одном городе

## Изменения в ходе реализации
В ходе разработки проведена оптимизация визуализации:
- Статическая карта Яндекс была заменена на интерактивную карту Leaflet, что позволяет пользователю видеть точное местоположение растения, масштабировать карту и проверять корректность определения города для прогноза погоды
- Добавлены интерактивные графики 5-дневного прогноза полива, которые показывают температуру, осадки и краткие рекомендации по поливу при наведении на каждый день, обеспечивая наглядную и удобную визуализацию информации
